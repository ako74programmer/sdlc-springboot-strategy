# GitHub Copilot Rules - existing project (brownfield)

This project was not generated by us. Its own code is the standard.

## Core Principles
1. **Source of truth**: `.\tools\sdlc.ps1` and its `sdlc-report.json`. Never claim a fix works without a pipeline run.
2. **Know the project first**: read `recon-report.json` (produced by `.\tools\recon.ps1`) before changing anything. It lists the build state, failing tests, coverage and the Java/Spring Boot versions in use.
3. **Baseline before the first change**: `.\tools\sdlc.ps1 -Baseline` records `sdlc-baseline.json`. Later runs compare against it (`Regression`, `TestIntegrity`, `DiffGuard`). Never re-record it after changes started.
4. **Follow the project's conventions**: package layout, naming, test style, libraries and Java/Spring Boot versions stay as they are unless the task says otherwise. Do not restyle the code to match a template.
5. **Minimal change**: touch only what the task requires. No drive-by refactoring, renames or reformatting of unrelated files.
6. **Tests prove the change**: a bug gets a failing test first (`.\tools\sdlc.ps1 -ReproTest Class#method`); a refactoring gets characterization tests first. Never weaken, delete or `@Disabled` an existing test to make the pipeline green.
7. **pom.xml may change** when the task needs it (vulnerable dependency, build fix, migration). Say why in a comment next to an overridden version.
8. **No suppression**: no `@SuppressWarnings`, `NOSONAR` or new Sonar exclusions to silence findings.
9. **HTTP errors stay client errors**: a catch-all `@ExceptionHandler(Exception.class)` turns framework errors (malformed JSON, wrong method, wrong `Content-Type`) into 500. Every new endpoint must answer 400 / 405 / 415 for them - extend `ResponseEntityExceptionHandler` or add handlers for `HttpMessageNotReadableException`, `HttpRequestMethodNotSupportedException`, `HttpMediaTypeNotSupportedException` - and a test proves it.
10. **XrayScan is mandatory**: vulnerable runtime dependencies are fixed in `pom.xml` in the same branch, also when they predate the task. Never finish with `-SkipXray`.
11. **Project JDK and Maven**: Maven must run on the JDK from `sdlc-settings.json` `javaHome` (matches the project's Java version) and, without a Maven Wrapper, with the Maven from `mavenHome` (the CI builder's version). `tools\sdlc.ps1` and `tools\recon.ps1` switch to both themselves; before running `mvn` by hand, run `.\tools\use-java.ps1` once in that terminal. Never change the Java version or compiler flags in `pom.xml` to work around a wrong JDK.
12. **Secrets stay untouched**: never read passwords or tokens from `~/.m2/settings.xml`, `*.token`, `sonar-token.txt`, `secrets.local.env` or environment variables, and never call Artifactory, Xray or SonarQube APIs with them. Use Maven (`dependency:get`, `versions:display-dependency-updates "-DprocessDependencyManagement=false"` - without that flag it queries every artifact of the Spring Boot BOM, about 20 minutes, even with `-Dincludes`) and `tools\*.ps1`, which handle credentials themselves. Credentials in configuration are `${ENV_NAME}` without a default; the user puts the values into `secrets.local.env` (never committed), which `tools\sdlc.ps1` and `tools\run-local.ps1` load.
13. **No real data**: never start the application against company environments (profiles that connect to real databases or services) and never store responses from them. Tests and the application start inside `mvn verify` are the evidence. Scratch files go to `target\sdlc-tmp\`, never to `C:\Temp` or the user profile.

## Report Format (`sdlc-report.json`)
- `status`: PASSED | FAILED
- `gates`: per-gate PASS/FAIL/SKIPPED
- `metrics.tests`, `metrics.coverage`
- `errors[]`: details per failed gate - fix exactly these, never guess.
